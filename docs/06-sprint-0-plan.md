# Plano da Sprint 0 — Fundação e Alinhamento

> Wikilink: [[Sprints]] · Sprint 0 — Fundação e Alinhamento

## Objetivo

Criar as bases para que o projeto caminhe com clareza: contexto, decisões, organização, colaboração e critérios para começar a entregar na Sprint 1.

## Entregáveis

- [x] [[Cérebro do Projeto]] ou equivalente, organizado com wikilinks.
- [x] [[Lean Canvas do Projeto]] com problema, público, proposta de valor e decisão de MVP.
- [x] [[Backlog v1]] priorizado por P0/P1/P2.
- [x] [[Arquitetura por Módulos]] com responsabilidade e regras de nearação.
- [x] [[Decisões Técnicas]] registradas.
- [x] [[Guia de Contribuição]] com critério de PR e checklist.
- [x] [[Glossário]] para termos-chave.

## O que foi definido agora

- Problema e público-alvo claros.
- Limite do MVP para revisão manual, com IA como assistente.
- Separação entre regras base e assistência IA.
- Módulos propostos com fronteiras.
- Critérios de aceite e colaboração.

## Condução desta sprint

- Foi apresentado ao usuário o resumo do projeto e a opção de continuar a decisão da Sprint 0.
- Foi escolhida a opção de continuar com condução própria.
- Decisão tomada: manter o foco em consolidar a documentação e o plano do projeto, sem pular direto para código sem um escopo definido.
- Próximo desfecho: fechar a Sprint 0 com os entregáveis já existentes e mais a documentação de condução/manutenção do projeto (convenções, critério de qualidade e usabilidade, estrutura para acompanhar evolução).

## O que fica para depois

- Escolha final de stack real.
- Definição de backend/serviço de IA concreto.
- Metodologia de teste automatizado específica.
- Detalhes de deploy e operação.
- Catálogo final de regras.

Esses itens podem ser criados ou ajustados nas próximas sprints à medida que o produto ganhar forma.

## Critério de prontidão para encerrar a Sprint 0

Para poder passar para a Sprint 1 com segurança, espera-se que:

- Qualquer pessoa no time consiga ler o [[Cérebro do Projeto]] e entender de onde o projeto veio.
- O backlog é legível e priorizado.
- As fronteiras de módulo fazem sentido e podem ser refinadas depois.
- As decisões mais importantes estão registradas.
- O time sabe como abrir issue, PR e contribuir.

## Lições desta sprint

- Começar por estrutura de documento evita repetição futura.
- Wikilinks funcionam bem enquanto o projeto é pequeno e coeso.
- Separar regra de IA desde o início reduz risco de confusão depois.
- Backlog pequeno e priorizado é mais útil do [[Backlog v1]] disperso por issues soltas.
- Quando o usuário pede continuação e depois delega a iniciativa, é melhor consolidar o plano antes de codar.
